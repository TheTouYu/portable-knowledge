# 会话历史深度分析：记忆使用行为与因果链

光统计"查没查知识树、报了多少错"，只能回答"崩没崩、忘没忘"。要回答
"长期记忆到底有没有让模型更高效"，必须从会话历史里重建**记忆行为**，并算出
**缺口代价**。分三层；`session-trace-extraction.md` 只覆盖 L1，本文件补 L2/L3。

## L1 统计层（回答"忘了没 / 崩没崩"）

错误计数、压缩次数、turn 结束原因、用户时间线——见 `session-trace-extraction.md`。

## L2 行为层（回答"记忆被用起来没有"）

从 `tool/call` 与 `assistant/message`(TEXT) 里重建 4 类行为：

1. **检索动作记录**：抓出所有记忆相关调用——`pkc`(`query` / `progressive-query` /
   `knowledge-search` / `show-claim` / `tree`)、`dsh-session-history`、读技能 `SKILL.md`、
   读 `docs/**`。对每一处"卡住"（TEXT 出现"卡住 / 不确定 / 先查一下 / 查一下 / 不知道"），
   标出**第一动作是不是检索**。
2. **检索有效性**：每次检索的关键词 → 命中 or 空。把"失手"分成三种，只有第三种是真正的记忆缺口：
   - **没查**：跳过记忆直接猜 / 考古代码（技能里有规则却没执行 → 检索纪律缺口）。
   - **查错方式**：`query` 没带 `--level 2`；`progressive-query` 中文长句 coverage gap 却不降级
     `query` / `knowledge-search --semantic`（规则已在 AGENTS.md，没执行 → 检索纪律缺口）。
   - **查了但载体确实缺**：gap 真实存在、知识树/文档/技能里没有 → 载体缺口。
3. **复用链**：跨会话边界处，模型是否主动 `dsh-session-history` 找回旧结论；找回后
   **直接复用**（记忆命中）还是**重新推导一遍**（记忆不被信任）。TEXT 标志：
   "找到了关键上下文 / 之前会话里 / 上个会话"。
4. **落盘时点**：结论从"闭合"到写进文档/技能/知识树隔了多久？是否出现
   "收尾时做"然后没做？（= 落盘纪律缺口）

## L3 因果层（回答"缺口花掉了什么"）

对 Phase 2 障碍清单里每个"返工 / 等用户实验 / 重复推导"，追一条四段链：

```text
行为：<会话里具体做了什么>（如 12:38 发现记录顺序非升序，推翻"追加末尾"假设）
缺口：<这条规则本该落在哪——技能 / 知识树 / 文档 / 账本？>
会话内检索：<模型有没有查它？查的结果？>（没查=纪律缺口；查了缺=载体缺口；查错=方式缺口）
代价：<多用了多少轮次 / 分钟 / 用户等待>
如果当时有：<能省什么，量化估计>
```

按此聚成两类结论，分别喂给 Phase 6：

- **载体缺口**：规则没落盘 → 补到文档 / 技能 / 知识树。
- **纪律缺口**：载体里有规则但会话内没执行（没查 / 查错 / 落盘拖延）→ 强化触发条件
  与检查项，而不是再加新知识（加新知识只会更避不开不执行问题）。

## 输出（进复盘报告的②③部分）

- 一张**记忆行为表**：每次卡住的第一动作、检索方式、命中结果、缺口归属（三类之一）。
- 一条**最高收益**：按代价（轮次 / 分钟 / 用户等待）排序，取代价最大、且能靠记忆消除的那条。

## 判断"有没有真提效"的最终口径

- L1 干净 ≠ 记忆有用——只说明没崩。
- L2 高检索率 + 低"查错方式" + 高复用 = 记忆**被真用起来**。
- L3 代价最小化 + 载体缺口逐轮收敛 = 记忆**在优化效率**。
- 三者一起看，缺一层的"结论"都不能当作效率证明。
